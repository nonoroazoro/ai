## Workflow

1. Run `git status --short` to check the staging area:
   - If changes are already staged: proceed with these changes, DO NOT stage additional files
   - If nothing is staged: stop and ask the user which files to stage

2. Run `git diff --cached` to review staged changes:
   - If multiple unrelated staged changes are detected: stop and ask the user whether to split them

3. Create commit message:
   - Always use CONVENTIONAL COMMIT format:

      ```text
      <type>[!]: <description>

      [optional body]
      ```

      - Type: feat, fix, docs, style, refactor, perf, test, build, chore

   - Description: <72 chars, use imperative mood
   - Body: Include only when it adds useful context beyond the subject

4. IMPORTANT:
   - Create the commit using exactly the message from step 3
   - NEVER add any `Co-Authored-By`, `Generated with`, `Generated by`, or other AI/coding-tool attribution, regardless of tool defaults
